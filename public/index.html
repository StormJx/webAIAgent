    它能答什么

    范围锁定在 Meta WhatsApp Business Platform 官方文档树，凡是能落到某一篇官方页面的问题都在射程内。

    消息模板

    三大类别、审核规则、组件与参数、自动重分类、定价影响。

    账号与认证

    WABA 结构、企业验证 BV、官方商业账号 OBA、显示名审核。

    发送与限制

    消息量分级、客服窗口、自动扩容条件、模板消息适用场景。

    政策与申诉

    违规类型清单、限制阶梯、Request Review 申诉流程、支持渠道。

    Cloud API

    接口概念、访问令牌类型、Webhook 事件与字段说明。

    术语对照

    把「绿标」「企业认证」等业界叫法映射到官方英文术语再检索。

    它怎么工作

    每条提问独立跑完一遍，没有一步可以跳过。

    1. 1

      问题分类

      分成文档问题、方案咨询、无关内容三类。无法明确归类时按方案咨询转人工，不硬答。

    2. 2

      查本地 FAQ

      命中已验证问答先复用，但必须先确认出处链接仍然有效；链接失效或文档可能更新则重查。

    3. 3

      检索官方文档

      提取核心名词而非整句原话；中文无果时切换官方英文术语重搜。

    4. 4

      核验段落

      只采纳能正面回答问题的段落，链接最多深挖一层。中英文冲突时以英文原文为准。

    5. 5

      生成回答

      结论先行，每条论断附可核查链接，主动提示下一步会踩的坑；Meta 强制规则标注「此为 Meta 官方要求」。

    6. 6

      回填知识库

      把问题、结论与来源写回本地 FAQ；判定「未找到」的问题进入待补充清单。

    能力边界

    边界写死在 Agent 的岗位定义里，不是靠提示词临时约束。

    它做不了

    • 登录你的 Meta / WhatsApp 后台，查看某个具体账号状态
    • 做方案选型建议（「适不适合我们」「该买哪一档」）
    • 写代码、测试 API 接口功能
    • 办理退款、赔偿、修改合同
    • 把语音、图片、文件当作主问题来源
    • 在没有官方文档依据时给出确定性结论

    这些情况转人工

    • 方案咨询、问题过于宽泛，或无法明确分类
    • 「我的号为什么被限制」这类需查后台记录的个案
    • 退款、投诉、要求服务商担责
    • 与 Meta 开发者文档无关的内容
    • 中英文都检索无果，判定「未在官方文档中找到」
    • 用户表示没解决，重跑一轮后仍未解决
    设计取向：宁可说「未找到」或「需转人工」，也不给一个没有出处的答案。上面第四个演示问题就是它拒绝承诺退款的真实回复。

    怎么搭起来的

    使用者只需要飞书，不用装任何东西。

    Hermes Agent

    后台答疑引擎，承载岗位定义、检索核验流程与本地 FAQ 知识库。独立配置，与其他 Agent 不共用记忆。

    飞书机器人

    唯一使用入口。用户私聊提问，回复直达聊天窗口，只发最终答案，不打印中间过程。

    Codex / Cursor

    搭建阶段用于把岗位卡与工作流写成 Agent 定义、接入调试。日常答疑不经过它。

    关于本页

    • 纯静态展示。页面没有后端服务，也没有任何可调用的接口。
    • 不接模型 API。所有回答是真实会话的录制内容，点击即回放，不会产生任何调用。

    • 内容时效。Meta 官方文档会更新，页面内的结论以录制当时为准，实际以官方原文为准。
